# Web App Orchestrator (フルスタックWebアプリ統括スキル)

このスキルは、フルスタックWebアプリケーションをゼロから高品質に構築するための**統括オーケストレータースキル**です。
ユーザーとの要件・デザイン合意を形成した後は、専門の**サブエージェント（Subagents）**を自律的に起動・連携させ、デザイン策定、画像アセット生成、バックエンド/DB、フロントエンド、ドキュメント、QA・自動デバッグを一貫して並行・高速に完遂します。

---

## 全体開発フロー (Orchestration Workflow)

```
[Phase 1: ヒアリング & 仕様合意] (対話的)
  ├── 要件・アーキテクチャ・技術スタックヒアリング
  └── 参考デザイン・トーン＆マナーのヒアリング
           │
           ▼
[Phase 2: 自律的並行開発] (オーケストレーターによるサブエージェント統括)
  ├── 🎨 Design & Assets Agent: デザイン定義書策定 + generate_image によるリアル素材生成
  ├── ⚙️ Backend & DB Agent: DBスキーマ・API・認証・ビジネスロジック実装
  ├── 💻 Frontend & UI Agent: コンポーネント・画面実装・デザイン定義書適用・API結合
  └── 📚 Docs & Config Agent: .env設定手順書・API仕様・READMEの並行整備
           │
           ▼
[Phase 3: QA & 自律デバッグ]
  └── 🧪 QA & Auto-Debug Agent: 起動テスト・ビルド検証・エラー自己修復ループ
           │
           ▼
[Phase 4: 完了報告 & 引き継ぎ]
  └── ユーザーへの起動方法・機能説明・ディレクトリ解説の提示
```

---

## 詳細ステップ

### 1. 仕様定義・デザインのヒアリング & 合意形成 (Interactive Phase)
- **いきなりコードを書き始めないでください。**
- **要件ヒアリング**: アプリの目的、主要機能、ユーザー導線、バックエンド要件（DB、認証、外部API等）を確認します。技術スタックの指定がない場合は、モダンな構成（Next.js + TypeScript + Tailwind CSS / Prisma / PostgreSQL など）を提案します。
- **デザインヒアリング**:
  - 参考WebサイトのURL（複数指定可）
  - 手持ちのデザイン画像やスクリーンショット
  - サイトで伝えたい印象やコンセプト・カラーイメージ
- 開発計画・アーキテクチャ・画面一覧のドラフトをユーザーに提示し、合意を得てから次の開発フェーズへ移行します。

---

### 2. プロジェクトの足場固め (Project Scaffolding)
- アプリケーションのルートディレクトリを作成し、CLIツール（`npx create-next-app` や `npm create vite` など）を非対話モードで実行、または手動でプロジェクト構造をセットアップします。

---

### 3. サブエージェントを活用した自律開発 (Subagent Autonomous Execution)
仕様合意後は、オーケストレーターとして以下の専門サブエージェントを自律的に起動し、並行して作業を推進します。

#### 🎨 Agent 1: Design & Visual Assets (デザイン＆画像生成)
- **役割**:
  - `design-master` スキルの規約に従い、`docs/design-spec.md`（デザイン定義書）および実装用デザイントークン（CSS変数 / Tailwind設定）を作成。
  - **画像アセット生成**: プレースホルダー（ダミー四角やプレースホルダーURL）を一切排除し、`generate_image` を活用して以下を生成・配置します。
    - **ブランディング素材**: サービスロゴ、ファビコン、アプリアイコン
    - **リアルコンテンツ画像**: 商品画像、記事サムネイル、ダミーアバター、ヒーロー/バナー画像
- **サブエージェント指示テンプレート例**:
  ```markdown
  Task: デザイン定義書の策定および画像アセットの生成
  - design-master の規約に従い docs/design-spec.md を作成
  - globals.css / tailwind.config にデザイントークンを組み込む
  - generate_image ツールを使用して、必要なロゴ・ファビコン・サムネイル・アバター画像を生成し、public/ または assets/ 配下に配置する
  - プレースホルダー画像は一切使用しないこと
  ```

#### ⚙️ Agent 2: Backend & Database (バックエンド & DB)
- **役割**:
  - DBスキーマ定義（Prisma / Drizzle / Supabase 等）とマイグレーションスクリプトの作成。
  - REST API / tRPC / Server Actions 等のエンドポイント実装。
  - 認証フロー、セッション管理、データバリデーション、ビジネスロジックの実装。
- **サブエージェント指示テンプレート例**:
  ```markdown
  Task: データベースおよびバックエンドAPIの実装
  - DBスキーマの作成とマイグレーションの準備
  - 仕様書に基づくAPIエンドポイント・認証・CRUDロジックの実装
  - モックデータではなく、実際にDBと通信しデータ永続化が動作する状態にする
  ```

#### 💻 Agent 3: Frontend & UI (フロントエンド & UI)
- **役割**:
  - デザイン定義書（`docs/design-spec.md`）のトークン（カラー、フォント、余白、タイポグラフィ）を100%遵守したUIコンポーネントの実装。
  - 状態管理およびバックエンドAPIとのデータバインディング（フロントエンドのモックで済ませず、Agent 2 のAPIと完全結合）。
  - レスポンシブ対応およびマイクロインタラクションの実装。
- **サブエージェント指示テンプレート例**:
  ```markdown
  Task: UI画面およびコンポーネントの実装
  - docs/design-spec.md を厳格に遵守したスタイリング
  - Agent 1 が生成した画像アセットを適切に配置・表示
  - Agent 2 のバックエンドAPIを呼び出し、実際のデータが画面に反映されるよう結合
  ```

#### 📚 Agent 4: Research & Documentation (調査 & ドキュメント)
- **役割**:
  - `.env.example` の作成と、ユーザーがローカルでアプリを動かすために必要な環境変数（APIキー、DB接続URLなど）の**取得・設定手順書**の作成。
  - ディレクトリ構造の解説、API仕様書のドキュメント化。
- **サブエージェント指示テンプレート例**:
  ```markdown
  Task: 設定ガイドおよびプロジェクトドキュメントの作成
  - .env.example の作成および環境変数の取得方法・設定手順を docs/setup.md に記述
  - README.md にシステム概要、起動手順、ディレクトリ構成をまとめる
  ```

---

### 4. QA & 自律デバッグ (QA & Auto-Debug Loop)
#### 🧪 Agent 5: QA & Auto-Debug Specialist
- **役割**:
  - `npm install`、`npm run build`、`npm run dev` などを実行し、ビルドや起動が正常に行われるか検証。
  - ブラウザ起動やAPIコールのテストを実施し、クラッシュや表示崩れ、ネットワークエラーを検出。
  - **自己修復ループ**: エラーが発生した場合は、**ユーザーの指示を待たずに自発的に原因を特定し、コードを修正**。確実に正常起動・動作するまで修正ループを回す。
- **サブエージェント指示テンプレート例**:
  ```markdown
  Task: プロジェクトのビルド・起動検証およびバグ自動修正
  - 依存関係のインストール、ビルド、起動コマンドを実行
  - エラーやワーニングが発生した場合は原因を分析し自律的に修正
  - アプリケーションがエラーなく正常稼働することを確認する
  ```

---

### 5. 完了報告と引き継ぎ (Completion & Handoff)
- 全てのサブエージェントの作業が完了し、QAテストを通過したことを確認。
- ユーザーに対して以下をチャット上で簡潔かつ分かりやすく提示します：
  1. **起動コマンド**（ワンライナーで動かせる手順）
  2. **初期設定ガイド**（`.env` の設定が必要な場合の案内）
  3. **実装した機能一覧と画面の確認ポイント**
  4. **ディレクトリ構成の概要**

---

## 統括ガイドライン (Orchestration Principles)

1. **オーケストレーターとしての統括**:
   - web-create は全体の進捗と各サブエージェント間の整合性を管理します。
   - バックエンドのAPI仕様とフロントエンドのリクエスト形式、デザイン定義書とコンポーネントのスタイリングが完全に一致していることを確認してください。

2. **自律性と自己修復 (Autonomous Completeness)**:
   - 「作って終わり」ではなく、「コマンドを実行すればそのまま動く状態」で納品します。
   - エラーが発生してもユーザーに丸投げせず、自律デバッグループで解決してください。

3. **リアルなアセットの徹底 (No Placeholders)**:
   - ダミー画像や灰色の四角形、`placeholder.com` は禁止です。`generate_image` を駆使して、本番さながらの高品質な画像アセットを配置してください。

4. **フルスタック連動の徹底**:
   - フロントエンドのモックデータで妥協せず、バックエンド・DBと連携して実際にデータが保存・取得・更新できる完全なアプリケーションを構築してください。
