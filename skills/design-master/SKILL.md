# Design Master (プロフェッショナルWebデザイン抽出・定義書策定スキル)

このスキルは、実在するプロフェッショナルなWebサイト（URL）やデザイン画像・スクリーンショットを解析し、**「AI特有の画一的なテンプレート感（AI感）」を排除したデザイン定義書（Style Guide）および実装用デザイントークンコード**を出力するスキルです。

`web-create` スキルと密接に連携し、Webアプリケーションの実装前に確定されたデザインシステムを提供します。

---

## 1. 入力パラメータ (Inputs)

ユーザーから以下の情報を受け取ります：

1. **参考サイトのURL（必須/複数可）**
   - 1つのサイトだけでなく、複数のサイトを指定可能。
   - 例：「配色はサイトA（URL_A）、カードやレイアウトはサイトB（URL_B）、ヘッダーの構成はサイトC（URL_C）」などの役割分担指定に対応。
2. **サイトで伝えたい印象や物事（必須）**
   - ブランドのコンセプト、世界観、ターゲットユーザー層、ユーザーに与えたい印象（例: 「堅実で信頼感のあるSaaS」「モダンでミニマルなクリエイティブスタジオ」「親しみやすく温かみのあるコミュニティ」など）。
3. **手持ちのデザイン画像・スクリーンショット（任意）**
   - ローカル画像パスや参考モックアップ画像がある場合、ビジュアル解析の対象とします。

---

## 2. 解析プロセス (Analysis Process)

### Step 1: 参考URL・リソースの解析
- ツール（`read_url_content` や `browser_subagent`）を活用し、対象サイトの構造・スタイル・ビジュアル情報を取得します。
- **DOM / CSS の解析**:
  - 主要な背景色、テキスト色、アクセントカラー、ボーダーカラーを抽出。
  - 使用されているフォントファミリー、フォントウェイト、見出しと本文の文字サイズ・行間の比率を算出。
  - パディング、マージン、グリッド幅（コンテナ幅）、角丸（border-radius）、シャドウ（box-shadow）のスケールを特定。
- 画像が提供された場合は、色彩バランスやレイアウトの構図を視覚的に分解します。

### Step 2: 「脱AI感（Anti-AI-look）」デザインフィルタの適用
AIが生成するWebデザインにありがちな以下の問題を意識的に排除します：

| AIにありがちな傾向 (NG) | Design Master が適用するプロ基準 (OK) |
| :--- | :--- |
| **安易な紫・シアンのネオングラデーション** | 実在ブランドのような、ブランドアイデンティティに根ざした深みのある配色、またはクリーンな中間色・ニュートラルグレーの調和 |
| **全要素への過度な角丸（pill型だらけ）** | 情報の性質に応じた適切な角丸（4px〜8pxを中心とした統制） |
| **意味のない過剰なガラスモーフィズム** | コンテクストに応じた実用的な面・線（Border）と繊細なシャドウによる階層表現 |
| **均一で単調な余白設定** | 4px/8pxベースのグリッドシステム。情報の親子関係（近接の法則）を際立たせるメリハリのある余白 |
| **デフォルトフォントの放置** | Google Fonts等からブランドのトーンに合致したフォント（例: Inter, Plus Jakarta Sans, Noto Sans JP, Outfit等）を明示選定し、文字詰め・行間を緻密に調整 |

---

## 3. 出力成果物 (Outputs)

本スキルは必ず以下の**2種類の成果物**を生成・出力します。

### ① デザイン定義書ドキュメント (`docs/design-spec.md`)
以下の構成でマークダウン仕様書を生成・保存します：

1. **デザインコンセプト & トーン＆マナー**
   - 伝えたい印象の言語化、キーワード（3〜5語）、ビジュアルの方向性。
2. **カラーパレット (Color Palette)**
   - ブランドカラー（Primary / Secondary）
   - サーフェス・背景色（Background / Card / Popover）
   - テキストカラー（Foreground / Muted Foreground）
   - アクセント・ボーダー（Accent / Border / Ring）
   - 各色のHEX値、HSL値、コントラスト比（WCAG基準）。
3. **タイポグラフィ (Typography)**
   - フォントファミリー（和文・欧文）
   - タイプスケール表（Display, H1〜H4, Body, Small, Caption の font-size / line-height / letter-spacing）
4. **スペーシング & レイアウト (Spacing & Layout)**
   - スペーシングスケール（4px, 8px, 12px, 16px, 24px, 32px, 48px, 64px）
   - コンテナ最大幅（Max Width）およびブレークポイント（sm, md, lg, xl）
5. **コンポーネントスタイル規約 (Components)**
   - ボタン（Primary, Secondary, Ghost, Outlineの通常・Hover・Active状態）
   - カード（シャドウ、ボーダー、パディング規約）
   - 入力フォーム（Input, Select, Checkbox）
   - ヘッダー / ナビゲーションのレイアウトと挙動

### ② 実装用デザイントークンコード
プロジェクトのフロントエンドコードに直接組み込める形式でコードを出力します：

1. **CSS変数定義（`globals.css` / `tokens.css`）**
   - HSLまたはHEX形式でCSSカスタムプロパティ（`--primary`, `--background`, `--radius` 等）を定義。ダークモード対応の変数切り替えも含める。
2. **Tailwind CSS 拡張設定（`tailwind.config.ts`）**
   - 抽出したカラー・フォント・余白を Tailwind の `theme.extend` にマッピングした設定コード。

---

## 4. `web-create` との連携フロー (Integration)

`web-create` と連携する際は、以下のシーケンスで実行されます：

1. ユーザーが `/web-create` を起動し、要件定義を行う際、`web-create` が参考サイトのURLおよび伝えたい印象をヒアリングします。
2. `web-create` は本 `design-master` の指示に従い、まず `docs/design-spec.md` とデザイントークンコードを生成・提示します。
3. ユーザーとデザインの合意（レビュー）を取った上で、生成されたデザイントークンをプロジェクト初期コード（`globals.css`, `tailwind.config.ts` 等）へ組み込み、画面実装を進めます。
4. UI実装時には、必ず `docs/design-spec.md` に記載されたカラー、フォント、余白、コンポーネント規約を100%遵守してコーディングを行います。
